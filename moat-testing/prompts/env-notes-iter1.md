Environment rules for this machine (operational constraints, not porting advice):
- This is a shared server. Other people's jobs run on GPUs 0-6. You may use exactly ONE GPU: an AMD Instinct MI300X (gfx942), PCI 0000:e5:00.0.
- Run anything that touches a GPU through /data/melliott/moat-testing/tools/rocm-run, which starts a container that can see only that GPU (it appears as device 0 inside). Usage: `rocm-run [--image IMAGE] bash -lc '<commands>'`; it mounts the current directory at the same path. Default image rocm/dev-ubuntu-24.04:7.2.1-complete matches the host ROCm 7.2.1. The current ROCm release is 10.1: rocm/dev-ubuntu-24.04:10.1.0-full (HIP 7.16, AMD clang 24) also runs on this GPU via `rocm-run --image rocm/dev-ubuntu-24.04:10.1.0-full ...`. You may pass another ROCm image with --image, or `docker build` a derived image (tag it moat-<something>), but never pass other /dev/dri devices or --privileged to docker, and never run multi-GPU jobs.
- Do not build or run GPU code directly on the host (the host has stale distro HIP headers in /usr/include that break host hipcc). Do not use sudo, do not install anything system-wide, do not touch Kubernetes. Containers and user-level installs inside this directory are fine.
- No NVIDIA GPU exists here. Docker images such as nvidia/cuda:12.8.1-devel-ubuntu24.04 can be pulled for compile-only work.
- Network access (git, pip, Hugging Face downloads) is available. Do not push anything anywhere, fork anything, or open PRs/issues.
- Keep all work inside your project directory.
- When you finish (or hit a hard block), write PORT_SUMMARY.md in the project root: what you changed and why, how to build and test, test results on the GPU, and anything left undone.
